## 〇、演示前准备（提前 5 分钟做）

### 1. 清场

```bat
:: 关掉所有 patient.exe / admin.exe
:: 删除运行期数据，保证是干净的初始状态
del D:\课设\课设\data\state.bin
```

> **为什么必须删**：`state.bin` 是上一次运行的共享数据（预约、队列、排班改动都在里面）。
> 不删的话演示时会出现别人留下的预约，容易讲乱。

### 2. 开两个窗口，都用共享模式

```bat
:: 窗口 1
cd /d D:\课设\课设
tools\run_qt.bat admin --shared

:: 窗口 2
cd /d D:\课设\课设
tools\run_qt.bat patient --shared
```

> **要看着两行输出**：
> 第一个窗口会打印「`[共享] 首次初始化共享数据区`」，
> 第二个打印「`[共享] 复用已有的共享数据`」。
> 这说明两端连的是**同一份数据**。

### 3. 确认两端连上

看任意一端的**左下角状态栏**：

```
[共享 · 对端 1 个：管理端 · 写计数 0]    ← 连上了
[单进程]                                ← 没连上，检查是不是漏了 --shared
```

## 二、场景 1：账户体系（2 分钟）

> **解决的问题**：上一次是所有人共用一份数据，谁都能改。真实系统里，患者只能看自己的。

### 演示步骤

**第 1 步：医院给新患者建档**

```
管理端 → 左侧「患者服务」→ 顶部二级标签「人员管理」
      → 左侧「新增患者」
      → 编号 P13（系统已自动填好）、姓名 赵强、电话 13800001313
      → 确定
```

**讲解词**：
> "注意这里 —— **注册是医院做的事，不是患者自己注册的**。真实医院就是这样：你先去服务台建档，之后才能在 App 上用。"

**第 2 步：患者端用姓名登录**

```
患者端 → 关掉，重新打开（或点「文件 → 重新装载数据」后重启）
      → 登录框输入「赵强」→ 登录
```

**讲解词**：
> "患者端启动第一件事是登录。输入姓名就能进，不用记账号密码 —— 因为到医院挂号本来也是报名字。
>
> 如果重名怎么办？系统会列出候选，用编号和电话后四位让你认领。
>
> 如果没建档？会明确提示『请先到医院服务台登记』，而不是让你卡在那儿。"

**第 3 步：展示权限边界**

```
患者端 → 「我的」→「预约管理」
      → 指着患者下拉框：「已变灰，不能切换」
```

**讲解词**：
> "登录之后，所有涉及『我是谁』的地方都锁定了。患者看不到别人的预约，也不能替别人签到。"

### 技术点（老师追问时讲）

- 登记时**两件事必须同时做**：
  1. 写进内存表 + 维护「编号 → 下标」的哈希索引（漏了就是装得进去查不出来）
  2. **追加一行到 `data/patients.txt`**（漏了就是删掉 `state.bin` 重新装载后人没了）
- 登录时按姓名做线性匹配，0 个 → 未建档，1 个 → 直接进，多个 → 让用户认领

## 三、场景 2：预约冲突检测（1.5 分钟）

> **解决的问题**：上一次存在一个真实缺陷 —— 同一个人可以在同一时段约两个不同科室，到那天两份凭证都有效，人却只有一个。

### 演示步骤

```
患者端 → 「预约」→ 在线预约
      → 医生选 D1 王秀英 → 点「周一上午」→ 生成预约凭证   ✅ 成功，记下凭证号 TKxxxx
      → 医生换成 D2 李思远（同一时段周一上午）→ 生成预约凭证
```

**结果**：弹出提示

```
你在该时段已有预约 TK0001，不能重复预约。请先到「预约管理」取消原预约。
```

**讲解词**：
> "这是这次补的一个**真实缺陷**。之前只要号源够，同一个人可以在周一上午同时约两个科室 —— 到那天两份凭证都有效、两边都能签到，但人只有一个。
>
> 现在会拦住，并且**告诉你冲突的是哪张凭证**，让你先去取消。"

### 技术点

- 检测函数 `BookingOps::sameSlotConflict()`：扫该患者所有「已预约」记录，若 `day`+`slot` 相同就返回凭证号
- **检查放在临界区内**（和号源扣减同一把锁），否则两个进程可能同时通过检查

## 四、场景 3：智能导诊 + 评分参与推荐（2 分钟）

> **解决的问题**：题目拓展要求第 3 条后半句 ——「**在科室预约推荐时参考评分**」。之前只做到"能评价能显示"，排序根本没用到评分。

### 演示步骤

```
患者端 → 「导诊」
      → 勾选：发热、咳嗽、胸闷
      → 点「开始导诊」
```

**指着结果表**：

| 列 | 说什么 |
|---|---|
| 科室 / 得分 | "科室排序只看**症状匹配度**（二部图边权求和）" |
| 该科室医生 | "医生排序用**评分 50% + 职称 30%**，括号里是患者实际打的分" |

**然后演示「一键去预约」**：

```
选中第一行 → 点「去预约该科室」或直接双击 → 自动跳到预约页并筛出该科室医生
```

**讲解词**：
> "这里有个设计取舍值得说：**我没有把评分直接加进科室得分**。
>
> 科室得分衡量的是『症状匹配度』，评分衡量的是『医生好不好』，两者数值范围都是 1~5，但含义完全不同。直接相加会出现『医生态度好』盖过『症状根本不匹配』的情况，推荐出无关科室。
>
> 所以做了**分层**：先用症状定科室，再在科室内用评分+职称+余号挑医生。这其实也是真实挂号的逻辑。"

### 技术点

- `DoctorRank::score()` = 评分 50% + 职称 30% + 该时段余号 20%
- 无人评价的医生评分项按 **60 分中性**处理（不惩罚新人，也不让他占便宜）
- 科室相似度用 **Jaccard**（症状集交集/并集）

> 这一段是**最能体现双端协作**的，建议重点演示。

### 第 1 步：患者签到

```
患者端 → 「候诊」→ 选中自己的预约 → 点「签到排队」
```

**指着卡片**：

### 第 2 步：医生叫号


**讲解词**：

>
> 有个规则叫『先来先看』：队首的人已经被叫过还没处理完，就不允许越过他去叫后面的人。"

>
> 而且同一条预约只能评一次。"

## 六、场景 5：停诊自动改约 + 换班（3 分钟）

> 题目的**拓展要求第 2 条**：「支持医生临时停诊**或换班**时自动通知已预约患者」。
> 这是之前**只做了一半**的地方。

### 第 1 步：停诊 + 自动改约

```
患者端先预约 2~3 条（不同患者、同一位医生的同一个时段）：
    可以用管理端「患者服务 → 预约管理」帮忙约
管理端 → 「排班管理」→ 视角「按医生」→ 选那位医生
      → 点一下那个号源格子选中
      → 点「设为停诊」
```

**结果提示**：
```
已停诊：D1 王秀英 周一上午。3 位患者已自动改约到其它时段（新凭证见其预约管理）
```

**讲解词**：
> "注意这里不只是『通知已停诊』。如果只通知，患者还得自己从头重约一遍 —— 这不是通知，是『通知你自己想办法』。
>
> 所以停诊时会同时帮他找替代时段，按优先级：**同医生同一天另一个时段 → 同医生其它天同时段 → 同科室其它医生同时段**。找到就生成新凭证，原记录标记为『因停诊改约』留痕。
>
> 找不到才退化成『因停诊取消』，并明确告诉管理者有几位没着落。"

### 第 2 步：换班（重点）

```
管理端 → 还是「排班管理」，选中另一个有预约的时段
      → 点「换班…」
```

弹出对话框：
```
当前：D1 王秀英 · 周一上午
换成：[D3 张淑华（主治医师 · 余号 15）▼]
该时段现有 1 条预约，会一起转给新医生。
```

**确定后**：
```
换班完成：周一上午 由 王秀英 改为 张淑华，1 条预约已随之转移
```

**讲解词（这是本场最重要的一段）**：
> "**停诊和换班的语义完全不同**，之前只做了停诊：
>
> | | 停诊 | 换班 |
> |---|---|---|
> | 号源 | 作废 | **保留**（还是那些号） |
> | 患者 | 要改约到别的时间 | **什么都不用改** |
> | 本质 | 这个时段不看病了 | 还看病，换个人看 |
>
> 现实场景：王医生周一上午临时有个会，让同科室张医生替她出这个门诊 —— 患者照常来、照常看，只是换了个大夫。这种情况**不能停诊**（停了患者要改时间），只能换班。
>
> 实现上最关键的是**余量校验**：目标医生那个时段装不装得下这些患者。装不下就拒绝，否则会超卖。"

### 技术点

```cpp
// Shift::transfer() 四步
① 校验原时段有排班、目标时段出诊且未停诊
② 先数清要转移多少条预约
③ if (目标余量 < 待转移条数) 拒绝        ← 防超卖
④ 预约记录的 doctor 字段改掉 + 号源在原时段清零、新时段加上
```

## 十、常见提问与回答

### Q1：为什么拆成两个程序？不是多此一举吗？

> "因为**两个角色的使用场景完全不同**：患者只关心自己的预约，管理端要管全院。放在一个界面里，要么患者能看到别人的数据，要么管理端被一堆无关按钮淹没。
>
> 拆开之后还逼出了并发问题 —— 两个进程改同一份数据，这正好是展示『怎么保证不冲突』的机会。"

### Q2：不用网络，两个程序怎么共享数据？

> "用的是 **内存映射文件 + 命名互斥体**。
>
> 两个进程映射同一个文件 `data/state.bin`，操作系统让它们共享同一批物理页，所以一方写入另一方立刻能看到，不需要传数据。
>
> 互斥体是 Windows 的命名内核对象，名字相同就是同一把锁，用 `WaitForSingleObject` / `ReleaseMutex` 做临界区。"

### Q3：数据量这么大（371KB），每次都整块同步会不会很慢？

> "**没有『同步』这个动作**。不是 A 把数据发给 B，而是两个进程看着同一块内存。延迟是内存级的，微秒级。
>
> 界面那边是轮询一个全局写计数（`generation`），发现变了才重读数据、重绘界面，每 700 毫秒检查一次。"

### Q4：万一两个人同时抢最后一个号呢？

> "『检查余量』和『扣减余量』在同一个临界区里，中间不让出 CPU，所以不可能两个人都通过检查。
>
> 压力测试验证过：不加锁时 4000 次并发操作丢 34%，加锁后 4000 次全部正确。"

### Q5：这些改动有没有破坏原来的功能？

> "字符界面版本一直在跑回归测试：`tools/check.bat` 把字符界面的输出和期望输出**逐字节比对**，一直是通过的。
>
> 而且业务层（service*.h）是共用的 —— 字符界面、患者端、管理端调的是同一批函数，所以只要回归过了，三端的行为是一致的。"

### Q6：评分为什么能影响推荐？不会把好科室挤掉吗？

> "不会，因为**分层**：科室排序只看症状匹配度，评分只参与**科室内医生**的排序。评分再高也不会让一个无关科室排到第一。"

### Q7：换班和停诊的区别再讲一遍？

> "停诊 = 这个时段**没号了**，患者要改时间；
> 换班 = 号**还在**，只是换个医生看，患者什么都不用改。
>
> 现实里医生临时有事，多半是找同事替，这是换班；如果找不到人替，才是停诊。"

## 十一、应急预案

| 情况 | 处理 |
|---|---|
| 状态栏显示「单进程」 | 少了 `--shared`，关掉重开 |
| 两端数据对不上 | 两个都关掉，删 `data\state.bin`，重新用 `--shared` 启动 |
| 号源数字看起来没变 | 确认看的是**同一位医生、同一个时段**；排班页按医生选 |
| 预约失败 | 看提示：号满 / 停诊 / 同时段已有预约 |
| 程序崩了 | 重新打开即可；`state.bin` 删掉不影响源码和数据文件 |
| 演示时间不够 | 砍掉场景 7（界面重构）和场景 6 的自检部分，保留 2、5、4 |
