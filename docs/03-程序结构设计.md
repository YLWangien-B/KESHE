# 3 程序结构设计

## 3.1 总体结构

系统采用**三层结构**，层与层之间单向依赖：

```
┌──────────────────────────────────────────────────────────────┐
│  界面层   main.cpp / ui.h / menu.h                            │
│     main.cpp   程序入口、主菜单、装载数据                        │
│     ui.h       表格对齐、读输入、暂停等界面辅助                   │
│     menu.h     六个功能的界面流程（要什么参数、怎么显示结果）        │
└───────────────────────────┬──────────────────────────────────┘
                            │ 调用
┌───────────────────────────▼──────────────────────────────────┐
│  业务层   service.h                                           │
│     Triage   智能导诊：按症状给科室打分并排序                     │
│     Route    就诊路线：查两点之间的最短路                         │
└───────────────────────────┬──────────────────────────────────┘
                            │ 读写
┌───────────────────────────▼──────────────────────────────────┐
│  数据层   model.h / load.h                                     │
│     model.h  实体定义 + 数据总库 Hospital（含全部数据表与索引）     │
│     load.h   从 6 个文本文件把数据读进总库                        │
└───────────────────────────┬──────────────────────────────────┘
                            │ 使用
┌───────────────────────────▼──────────────────────────────────┐
│  数据结构层   ds.h                                             │
│     SeqList  顺序表      RingQueue 环形队列                     │
│     HashMap  散列表      RoadNet   邻接矩阵图（含 Floyd）         │
└──────────────────────────────────────────────────────────────┘
```

**依赖规则**：

| 层 | 可以用 | 不可以 |
| --- | --- | --- |
| 数据结构层 | C++ 语言本身 | 依赖上面任何一层 |
| 数据层 | 数据结构层 | 依赖业务层、界面层 |
| 业务层 | 数据层、数据结构层 | 依赖界面层、直接读文件、直接 printf 结果 |
| 界面层 | 业务层、数据层（只读） | 自己实现业务算法 |

**为什么业务层不打印任何东西**：`Triage::run` 和 `Route::between` 只把结果算出来返回，
至于怎么显示由界面层决定。好处是将来换成图形界面时，业务层一行都不用改。

## 3.2 各文件的职责与接口

### 3.2.1 `ds.h` — 数据结构层

| 类型 | 主要接口 |
| --- | --- |
| `SeqList<T, N>` | `push` `removeAt` `size` `empty` `full` `[i]` `clear` |
| `RingQueue<T, N>` | `push` `pop` `at(i)` `size` `empty` `full` `clear` |
| `HashMap` | `put(key, value)` `get(key, out)` `size` `clear` |
| `RoadNet` | `init(n)` `addEdge(u,v,w)` `floyd()` `distance(u,v)` `reachable(u,v)` `buildPath(u,v,path,cap)` |

### 3.2.2 `model.h` — 数据层

**实体**（都是定长记录，内部不存指针，可以整体拷贝）：

| 结构 | 字段 |
| --- | --- |
| `Department` | 编号、名称、位置、关联症状下标数组、对应权重数组、症状个数 |
| `Doctor` | 编号、姓名、科室下标、职称、擅长领域、房间下标、（评分累计与人数字段留给扩展功能） |
| `Room` | 编号、名称、楼层、科室下标、路网节点号 |
| `Symptom` | 症状名 |
| `Schedule` | 最大接诊数、已预约数、版本号、是否已排班、是否停诊 |
| `Patient` | 编号、姓名、电话 |
| `Booking` | 凭证号、患者下标、医生下标、日期、时段、状态 |

**数据总库 `Hospital`**：把全部数据表、索引和路网集中在一个对象里。

```cpp
class Hospital {
 public:
  Schedule schedule[kMaxDoctor][kMaxDay][kMaxSlot];  // 排班：下标就是主键

  SeqList<Department, kMaxDept> depts;
  SeqList<Doctor,   kMaxDoctor> doctors;
  SeqList<Patient,  kMaxPatient> patients;
  SeqList<Booking,  kMaxBook>   bookings;
  SeqList<Room,     kMaxRoom>   rooms;
  SeqList<Symptom,  kMaxSymptom> symptoms;

  RoadNet road;                 // 全院路网

  HashMap deptIndex, doctorIndex, patientIndex, roomIndex;

  int ticketSeq;                // 凭证号自增序号
  int versionClock;             // 版本时钟

  void clear();
  int  findDept(const char*) const;      // 编号 -> 下标，查不到返回 -1
  int  findDoctor(const char*) const;
  int  findPatient(const char*) const;
  int  findRoom(const char*) const;
  Schedule& slot(int doctor, int day, int s);       // 排班槽定位
  bool hasSchedule(int doctor, int day, int s) const;
  int  remaining(int doctor, int day, int s) const; // 剩余号源
  int  findRoomByNode(int node) const;              // 路网节点 -> 房间
  int  roomsOfDept(int dept, int* out, int cap) const;
};
```

**总库为什么用函数内静态对象**：`sizeof(Hospital)` 约 60 KB，虽然没有超过默认的
1 MB 线程栈，但把一个大对象放在栈上不是好习惯（将来加表就可能溢出）。
统一用 `db()` 返回一个静态实例，各模块共享同一份数据，不会出现状态不一致。

```cpp
// main.cpp 里定义，model.h 里声明，各模块统一调用
Hospital& db() {
  static Hospital instance;
  return instance;
}
```

### 3.2.3 `load.h` — 数据装载

对外只有一个接口：

```cpp
Loader::loadAll(Hospital& h, "data")   // 成功返回 true
Loader::errorCount()                   // 有多少行数据没通过校验
```

内部按外键依赖顺序装载，顺序不能颠倒：

```
symptoms.txt ──► depts.txt（科室的关联症状要按症状名去查）
                  │
                  ├──► doctors.txt（医生属于某个科室）
                  │      │
                  │      └──► schedules.txt（排班引用医生）
                  │
                  └──► layout.txt（房间的科室字段引用科室）
                         │
                         └──► 装载完后把医生的房间号翻译成房间下标
                              （医生文件里写的是房间号，但那时房间还没读进来）
```

装载完成后调用 `road.floyd()` 做一次性的最短路预计算。

**数据出错时的处理**：某一行字段不够、编号查不到、同一医生同一时段重复排班，
都跳过该行、打印一行告警并计数，**不中断整个装载**。
这样数据文件有小毛病时程序仍能起来，便于排查。

### 3.2.4 `service.h` — 业务层

```cpp
// 智能导诊
constexpr int kMaxTriageResult = 5;   // 最多推荐几个科室
constexpr int kMaxPick = 8;           // 一次最多勾选几个症状

struct TriageItem {
  int dept;                          // 科室下标
  int score;                         // 匹配得分
  int matchCount;                    // 命中症状数
  int matched[kMaxSympPerDept];      // 命中的症状下标（用来说明推荐依据）
};
struct TriageResult { TriageItem items[kMaxTriageResult]; int count; };

class Triage {
  static TriageResult run(const Hospital& h, const int* picked, int pickCount);
};

// 就诊路线
constexpr int kMaxRouteSteps = 16;

struct RouteResult {
  bool found;
  int  totalDistance;                // 全程距离（米）
  int  steps[kMaxRouteSteps];        // 途经的房间下标
  int  stepCount;
  int  floorChanges;                 // 换层次数
};

class Route {
  static RouteResult between(const Hospital& h, int fromRoom, int toRoom);
};
```

### 3.2.5 `ui.h` / `menu.h` / `main.cpp` — 界面层

| 文件 | 职责 |
| --- | --- |
| `ui.h` | `width()` 算显示宽度、`cell()` 输出定宽单元格、`readLine()` / `readInt()` 读输入、`pause()` 暂停 |
| `menu.h` | `doTriage` `doQueryDoctor` `doBook` `doManageBooking` `doShowSchedule` `doRoute` 六个函数，一个功能一个函数 |
| `main.cpp` | 定义 `db()`，装载数据，打印主菜单，根据选择调用 `menu.h` 里的函数 |

## 3.3 关键流程

### 3.3.1 启动与装载

```
main()
 ├─ setupConsole()                把控制台代码页切到 UTF-8
 ├─ Loader::loadAll(db(), "data")
 │    ├─ h.clear()                清空所有表、索引、排班标记
 │    ├─ loadSymptoms()           symptoms.txt  → 症状表
 │    ├─ loadDepts()              depts.txt     → 科室表（关联症状按名字查症状下标）
 │    ├─ loadDoctors()            doctors.txt   → 医生表（科室编号查科室下标）
 │    ├─ loadSchedules()          schedules.txt → 排班三维数组（按下标放入格子）
 │    ├─ loadPatients()           patients.txt  → 患者表
 │    ├─ loadLayout()             layout.txt    → 房间表 + 路网（读两遍建图）
 │    └─ road.floyd()             一次性算出任意两点最短路
 ├─ 打印装载统计与告警
 └─ 主菜单循环
```

### 3.3.2 智能导诊

```
用户勾选症状（如「4 2 6」）
   │
   ├─ 把序号解析成症状下标数组
   ├─ Triage::run(h, picked, pickCount)
   │    ├─ 对每个科室：遍历它的关联症状，命中就累加权重 → score
   │    ├─ score > 0 的科室按插入排序放进结果（最多 5 条，满了就挤掉最低分）
   │    └─ 记录每个科室命中了哪些症状，供界面显示「推荐依据」
   └─ 界面打印：序号、科室、得分、依据、位置
        并顺便列出该科室前 3 名医生，方便患者接着去预约
```

### 3.3.3 在线预约

```
输入患者编号 → 查散列表得到患者下标
输入医生编号 → 查散列表得到医生下标（界面先打出该医生一周排班表）
输入日期与时段
   │
   ├─ h.hasSchedule(doctor, day, slot)?  没有 → 提示「该医生此时段不出诊」
   ├─ 记下 version = s.version            ← 取号：记下当前版本号
   ├─ s.stopped?                          是 → 提示「该时段已停诊」
   ├─ s.quota - s.booked <= 0?            是 → 提示「号源已满」
   ├─ s.version != version?               是 → 提示「号源刚刚变化，请重选」
   │                                             （这三步与下一步合起来是原子的）
   ├─ ++s.booked; s.version = ++h.versionClock      ← 扣减号源
   ├─ 生成预约记录，凭证号 TK + 自增序号
   └─ 打印预约凭证：凭证号、患者、科室、医生、时间、地点、剩余号源
```

**关于并发安全**：真实医院有多个挂号窗口同时工作，两个人可能都读到「剩 1 号」，
然后都扣减成功，造成超卖。系统用**版本号**来防止这件事：取号时记下版本，
扣减前再比一次，版本对不上就说明这期间有人动过号源，拒绝这次预约让患者重选。
这几步之间没有让出执行权的位置，所以是原子的。
这种「先假设不冲突，提交时才校验」的做法叫**乐观锁**。

### 3.3.4 就诊路线

```
输入起点、终点房间号
   │
   ├─ h.findRoom() 查散列表得到房间下标
   ├─ Route::between(h, a, b)
   │    ├─ 取两个房间的 node（路网节点号）
   │    ├─ road.reachable(u, v)?          否 → 返回「不连通」
   │    ├─ r.totalDistance = road.distance(u, v)      O(1) 查表
   │    ├─ road.buildPath(u, v, path, 16)             顺 next 链还原路径
   │    ├─ 把节点号翻译回房间下标
   │    └─ 统计换层次数（相邻节点楼层不同的次数）
   └─ 界面打印节点序列与累计距离，再从换层处给出「乘电梯 / 走楼梯」的指引
```

## 3.4 出错处理约定

| 场景 | 处理方式 |
| --- | --- |
| 数据文件打不开 | `loadAll` 返回 false，提示「请先运行 build\gen_data.exe data」，程序退出 |
| 某行字段不够 | 跳过该行，打印告警并计数，继续装载 |
| 外键找不到（如医生写的科室编号不存在） | 跳过该行，打印告警并计数 |
| 同一医生同一时段重复排班 | 拒绝该行，打印告警（否则会把已有排班覆盖掉） |
| 编号重复 | 后一条覆盖前一条的索引，编号索引以最后一条为准 |
| 容量不足 | `SeqList::push` 返回 -1，跳过并计数，不做隐式扩容 |
| 按编号查不到 | `findXxx` 返回 -1，调用方必须判断 |
| 两点不连通 | `Route::between` 返回 `found = false`，界面提示不连通 |
| 号源状态变化 | 提示「号源状态刚刚发生变化，请重新选择」，不静默失败 |
| 菜单输入非数字 | `atoi` 得到 0，等同于退出；不崩溃 |

## 3.5 类图（简化）

```
        ┌──────────────────────────────────┐
        │            Hospital              │
        ├──────────────────────────────────┤
        │ schedule[][][] : Schedule        │◆──┐ 组合
        │ depts     : SeqList<Department>  │   │
        │ doctors   : SeqList<Doctor>      │   │
        │ patients  : SeqList<Patient>     │   │
        │ bookings  : SeqList<Booking>     │   │
        │ rooms     : SeqList<Room>        │   │
        │ symptoms  : SeqList<Symptom>     │   │
        │ road      : RoadNet              │◆──┤
        │ deptIndex ... roomIndex : HashMap│◆──┤
        ├──────────────────────────────────┤   │
        │ +clear()                         │   │
        │ +findDept/findDoctor/...         │   │
        │ +slot() +hasSchedule()           │   │
        │ +remaining() +findRoomByNode()   │   │
        └───────────────┬──────────────────┘   │
                        │ 引用（聚合）           │
        ┌───────────────┴──────────────┐       │
        │                              │       │
┌───────▼────────┐          ┌──────────▼────┐  │
│    Triage      │          │    Route      │  │
├────────────────┤          ├───────────────┤  │
│ +run(h, ...)   │          │ +between(...) │  │
└────────────────┘          └───────────────┘  │
                                               │
   ┌───────────────────────────────────────────┘
   │ 被组合的四种数据结构
┌──▼───────────┐ ┌──────────────┐ ┌─────────────┐ ┌──────────────────────┐
│ SeqList<T,N> │ │ RingQueue<T,N>│ │ HashMap     │ │ RoadNet              │
├──────────────┤ ├──────────────┤ ├─────────────┤ ├──────────────────────┤
│ data_[N]     │ │ data_[N]     │ │ node_[1024] │ │ dist_[128][128]      │
│ n_           │ │ head_ tail_ n_│ │ head_[211]  │ │ next_[128][128]      │
├──────────────┤ ├──────────────┤ ├─────────────┤ ├──────────────────────┤
│ +push()      │ │ +push()      │ │ +put()      │ │ +init() +addEdge()   │
│ +removeAt()  │ │ +pop()       │ │ +get()      │ │ +floyd()             │
│ +size() [i]  │ │ +at(i)       │ │ +clear()    │ │ +distance()          │
└──────────────┘ └──────────────┘ └─────────────┘ │ +buildPath()         │
                                                  └──────────────────────┘
```

（`◆` 是组合：`Hospital` 拥有这些数据结构；`Triage` 和 `Route` 只是持有
`Hospital&`，属于聚合，它们不拥有数据。）

## 3.6 后续阶段的实现计划

| 功能 | 需要新增 | 复用已有的什么 |
| --- | --- | --- |
| E1 候诊队列 | `menu.h` 加一个菜单项；`model.h` 里给每位医生加一条 `RingQueue` | `ds.h` 的 `RingQueue` 已经写好 |
| E2 停诊通知 | `Hospital` 加通知表；`menu.h` 加菜单项 | 排班槽按下标定位、顺序表遍历预约 |
| E3 患者评价 | `Doctor` 的 `rankSum` / `rankCount` 字段已经留好；导诊排序时叠加评分 | `Triage::run` 里加一行加成 |
| E4 转诊推荐 | `Triage` 加一个 `similarDepts()` 函数 | 科室的关联症状数组直接当集合用 |
| E5 文本导诊 | 症状表加同义词字段；新增一个分词函数 | 二部图打分完全不变 |

扩展功能都**不需要改动数据结构层**，这也说明目前的结构划分是合理的：
主干稳定，扩展只在业务层和界面层加东西。
