# 3 程序结构设计

## 3.1 总体结构

系统采用**三层结构**，层与层之间单向依赖：

```
┌──────────────────────────────────────────────────────────────┐
│  界面层   main.cpp / ui.h / menu.h / menu_queue.h             │
│     main.cpp       程序入口、主菜单、装载数据                    │
│     ui.h           表格对齐、读输入、暂停等界面辅助               │
│     menu.h         功能 1~6 的界面流程                          │
│     menu_queue.h   功能 7 候诊队列的界面流程（含子菜单）           │
└───────────────────────────┬──────────────────────────────────┘
                            │ 调用
┌───────────────────────────▼──────────────────────────────────┐
│  业务层   service.h / service_queue.h                          │
│     Triage   智能导诊：按症状给科室打分并排序                     │
│     Route    就诊路线：查两点之间的最短路                         │
│     Queue    候诊队列：签到、叫号、过号、就诊完成                  │
└───────────────────────────┬──────────────────────────────────┘
                            │ 读写
┌───────────────────────────▼──────────────────────────────────┐
│  数据层   model.h / load.h                                     │
│     model.h  实体定义 + 数据总库 Hospital（含全部数据表与索引）     │
│     load.h   从 6 个文本文件把数据读进总库                        │
└───────────────────────────┬──────────────────────────────────┘
                            │ 使用
┌───────────────────────────▼──────────────────────────────────┐
│  数据结构层   ds.h                                             │
│     SeqList        顺序表        RingQueue      环形队列          │
│     HashMap        散列表        WeightedGraph  带权图（Floyd）    │
│     ScheduleTable  二维数组（日期×时段）                            │
│     BipartiteGraph 带权二部图（症状—科室）                          │
└──────────────────────────────────────────────────────────────┘
```

**依赖规则**：

| 层 | 可以用 | 不可以 |
| --- | --- | --- |
| 数据结构层 | C++ 语言本身 | 依赖上面任何一层 |
| 数据层 | 数据结构层 | 依赖业务层、界面层 |
| 业务层 | 数据层、数据结构层 | 依赖界面层、直接读文件、直接 printf 结果 |
| 界面层 | 业务层、数据层（只读） | 自己实现业务算法 |

**为什么业务层不打印任何东西**：`Triage::run` 和 `Route::between` 只把结果算出来返回，
至于怎么显示由界面层决定。好处是将来换成图形界面时，业务层一行都不用改。

## 3.2 各文件的职责与接口

### 3.2.1 `ds.h` — 数据结构层

| 类型 | 主要接口 |
| --- | --- |
| `SeqList<T, N>` | `push` `removeAt` `size` `empty` `full` `[i]` `clear` |
| `RingQueue<T, N>` | `push` `pop` `at(i)`（可写）`removeAt(i)` `size` `empty` `full` `clear` |
| `HashMap` | `put(key, value)` `get(key, out)` `size` `clear` |
| `ScheduleTable<日期, 时段>` | `slot(d,s)` `assigned(d,s)` `remaining(d,s)` `validDay` `validSlot` `clear` |
| `insertSorted`（在 `ds_sort.h`） | `insertSorted(a, n, cap, v, less)`；规则可用 `GreaterScore` / `Ascending<T>` |
| `WeightedGraph` | `init(n)` `addEdge(u,v,w)` `floyd()` `distance(u,v)` `reachable(u,v)` `buildPath(u,v,path,cap)` |
| `BipartiteGraph` | 顶点：`addSymptom` `findSymptom` `symptomName` `symptomCount` `setDepartmentCount`<br>边：`addEdge(s,k,w)` `weightOf(s,k)` `edgeCount`<br>遍历：`firstDeptOf` `nextDeptEdge` `edgeDept` `edgeWeight`（症状→科室）<br>遍历：`firstSymptomOf` `nextSymptomEdge` `edgeSymptom`（科室→症状） |

> `BipartiteGraph` 的遍历接口分成两组，是因为二部图的两侧各有一条邻接链。
> 每条边在边集中占两个结点、两侧各挂一次，两个结点各有自己的 `next`。
> 这一点写错的话，症状能查到科室、科室却查不到症状。

### 3.2.2 `model.h` — 数据层

**实体**（都是定长记录，内部不存指针，可以整体拷贝）：

| 结构 | 字段 |
| --- | --- |
| `Department` | 编号、名称、位置、**一句描述文本**（里面写出常见症状词，供导诊匹配） |
| `Doctor` | 编号、姓名、科室下标、职称、擅长领域、房间下标、**一张 日期×时段 二维排班表**、（评分累计与人数字段留给扩展功能） |
| `Room` | 编号、名称、楼层、科室下标、路网节点号 |
| `ScheduleSlot` | 最大接诊数、已预约数、版本号、是否已排班、是否停诊 |
| `Waiting` | 患者下标、医生下标、排队号、已叫号次数 |
| `Patient` | 编号、姓名、电话 |
| `Booking` | 凭证号、患者下标、医生下标、日期、时段、状态 |

> **症状不在这张表里**：按题目实现提示第 1 条，症状是带权二部图症状侧的顶点，
> 存放在 `Hospital::symptomGraph` 中（顶点名 + 邻接链）。
> 科室的症状关联同理，是二部图的边而不是科室记录里的数组。
> 这样同一个关系只有一份数据。

**数据总库 `Hospital`**：把全部数据表、索引、图和队列集中在一个对象里。

```cpp
class Hospital {
 public:
  SeqList<Department, kMaxDept>   depts;
  SeqList<Doctor,   kMaxDoctor>   doctors;
  SeqList<Patient,  kMaxPatient>  patients;
  SeqList<Booking,  kMaxBook>     bookings;
  SeqList<Room,     kMaxRoom>     rooms;

  BipartiteGraph symptomGraph;    // 症状—科室 带权二部图（导诊用）
  RingQueue<Waiting, kMaxWaiting> waiting;   // 候诊队列（环形队列）
  WeightedGraph  road;            // 全院路网（邻接矩阵 + Floyd）

  HashMap deptIndex, doctorIndex, patientIndex, roomIndex;

  int ticketSeq;                  // 凭证号自增序号
  int versionClock;               // 版本时钟

  void clear();
  int  findDept(const char*) const;      // 编号 -> 下标，查不到返回 -1
  int  findDoctor(const char*) const;
  int  findPatient(const char*) const;
  int  findRoom(const char*) const;
  ScheduleSlot& slot(int doctor, int day, int s);   // 排班槽：先定位医生，再按下标取
  bool hasSchedule(int doctor, int day, int s) const;
  int  remaining(int doctor, int day, int s) const; // 剩余号源
  int  findRoomByNode(int node) const;              // 路网节点 -> 房间
  int  roomsOfDept(int dept, int* out, int cap) const;
};
```

**总库为什么用函数内静态对象**：`sizeof(Hospital)` 约 60 KB，虽然没有超过默认的
1 MB 线程栈，但把一个大对象放在栈上不是好习惯（将来加表就可能溢出）。
统一用 `db()` 返回一个静态实例，各模块共享同一份数据，不会出现状态不一致。

```cpp
// main.cpp 里定义，model.h 里声明，各模块统一调用
Hospital& db() {
  static Hospital instance;
  return instance;
}
```

### 3.2.3 `load.h` — 数据装载

对外只有一个接口：

```cpp
Loader::loadAll(Hospital& h, "data")   // 成功返回 true
Loader::errorCount()                   // 有多少行数据没通过校验
Loader::overflowCount()                // 有多少处数据超出了容量上限
```

内部按外键依赖顺序装载，顺序不能颠倒：

```
symptoms.txt ──► 二部图的症状顶点
                  │
depts.txt    ──► 科室表 + 二部图的科室顶点与边（边要按症状名去查症状顶点）
                  │
                  ├──► doctors.txt（医生属于某个科室）
                  │      │
                  │      └──► schedules.txt（排班引用医生）
                  │
                  └──► layout.txt（房间的科室字段引用科室）
                         │
                         └──► 装载完后把医生的房间号翻译成房间下标
                              （医生文件里写的是房间号，但那时房间还没读进来）
```

装载完成后调用 `road.floyd()` 做一次性的最短路预计算。

**二部图顶点数与边的关系**：二部图的边要求两个端点都已存在，所以装载时必须
**先把顶点登记好、再连边**。科室顶点数在读到第一个科室时设定一次
（调 `setDepartmentCount` 会清空全部科室的邻接链头，只能调一次），
之后逐行加边。装载流程里绝不能在读完科室表之后又调一次
`setDepartmentCount` —— 那会把刚建好的边全部丢掉。

**数据出错时的处理**：某一行字段不够、编号查不到、同一医生同一时段重复排班，
都跳过该行、打印一行告警并计数，**不中断整个装载**。
这样数据文件有小毛病时程序仍能起来，便于排查。

**容量不足单独计数**：数据表的容量是编译期常量，超了就会丢记录。
这种情况与「某几行数据写错了」性质不同，因此用 `overflowCount()` 单独计数，
提示语里会指出是哪个表超了、该调大哪个常量。

### 3.2.4 `service.h` — 业务层

```cpp
// 智能导诊
constexpr int kMaxTriageResult  = 5;   // 最多推荐几个科室
constexpr int kMaxPickedSymptom = 8;   // 一次最多参考几个症状

struct TriageItem {
  int dept;                            // 科室下标
  int score;                           // 匹配得分
  int matchCount;                      // 命中症状数
  int matched[kMaxMatchedPerDept];     // 命中的症状顶点号（用来说明推荐依据）
};
struct TriageResult {
  int picked[kMaxPickedSymptom];       // 患者选中的症状顶点号
  int pickedCount;                     // 选了几个
  TriageItem items[kMaxTriageResult];
  int count;                           // 推荐了几个科室
  bool hasPicked(int symptom) const;   // 某症状是否被选中
};

class Triage {
  static TriageResult run(const Hospital& h, const int* picked, int pickCount);
};

// 就诊路线
constexpr int kMaxRouteSteps = 16;

struct RouteResult {
  bool found;
  int  totalDistance;                // 全程距离（米）
  int  steps[kMaxRouteSteps];        // 途经的房间下标
  int  stepCount;
  int  floorChanges;                 // 换层次数
};

class Route {
  static RouteResult between(const Hospital& h, int fromRoom, int toRoom);
};
```

## 3.3 关键流程

### 3.3.1 启动与装载

```
main()
 ├─ setupConsole()                把控制台代码页切到 UTF-8
 ├─ Loader::loadAll(db(), 数据目录)
 │    ├─ h.clear()                清空所有表、索引、二部图、队列、排班标记
 │    ├─ loadSymptoms()           symptoms.txt  → 二部图的症状顶点
 │    ├─ loadDepts()              depts.txt     → 科室表 + 科室顶点 + 二部图的边
 │    ├─ loadDoctors()            doctors.txt   → 医生表（科室编号查科室下标）
 │    ├─ loadSchedules()          schedules.txt → 排班二维数组（日期、时段两个下标）
 │    ├─ loadPatients()           patients.txt  → 患者表
 │    ├─ loadLayout()             layout.txt    → 房间表 + 路网（读两遍建图）
 │    └─ road.floyd()             一次性算出任意两点最短路
 ├─ 打印装载统计；有校验错误或容量不足则明确提示
 └─ 主菜单循环
```

### 3.3.2 智能导诊

```
患者在症状表里按序号选出自己的症状（如「4 2 6」）
   │
   ├─ 把序号解析成症状顶点号，越界的跳过并告知；同一症状选两次只算一次
   ├─ Triage::run(h, picked, pickCount)
   │    ├─ 记下患者选了哪些症状（界面显示「依据」用）
   │    └─ 对每个科室沿「科室 → 关联症状」这条邻接链走一遍：
   │         命中的症状就把边权累加到 score（二部图上的邻域加权求和）
   │         score > 0 的按插入排序放进结果（最多 5 条，满了就挤掉最低分）
   └─ 界面打印：序号、科室、得分、推荐依据（命中的症状）、位置，
        再显示该科室的主诉范围（科室描述），
        并顺便列出该科室前 3 名医生，方便患者接着去预约
```

### 3.3.3 在线预约

```
输入患者编号 → 查散列表得到患者下标
输入医生编号 → 查散列表得到医生下标（界面先打出该医生一周排班表）
输入日期与时段
   │
   ├─ 在医生记录的二维排班表上按下标取槽：h.slot(doctor, day, slot)
   ├─ h.hasSchedule(doctor, day, slot)?  没有 → 提示「该医生此时段不出诊」
   ├─ s.stopped?                          是 → 提示「该时段已停诊」
   ├─ s.quota - s.booked <= 0?            是 → 提示「号源已满」
   ├─ ++s.booked; s.version = ++h.versionClock      ← 扣减号源，并换一个新版本号
   │      （上面的检查与这里的扣减连着做完，中间不让出执行权，因此不会超卖）
   ├─ 生成预约记录，凭证号 TK + 自增序号
   └─ 打印预约凭证：凭证号、患者、科室、医生、时间、地点、剩余号源
```

**关于并发安全**：真实医院有多个挂号窗口同时工作，两个人可能都读到「剩 1 号」，
然后都扣减成功，造成超卖。系统用**版本号 + 检查与扣减连续完成**来防止这件事：
三步检查（停诊、余量、版本）与扣减之间没有让出执行权的位置，所以这一段是原子的；
同时每个槽带一个版本号，任何号源变动都会把它换成版本时钟的下一个值，
于是「此前看到的余号信息」立刻作废，拿着旧版本去扣减会被拒绝并要求重选。
这种「先假设不冲突，提交时才校验」的做法叫**乐观锁**。

### 3.3.4 就诊路线

```
输入起点、终点房间号
   │
   ├─ h.findRoom() 查散列表得到房间下标
   ├─ Route::between(h, a, b)
   │    ├─ 取两个房间的 node（路网节点号）
   │    ├─ road.reachable(u, v)?          否 → 返回「不连通」
   │    ├─ r.totalDistance = road.distance(u, v)      O(1) 查表
   │    ├─ road.buildPath(u, v, path, 16)             顺 next 链还原路径
   │    ├─ 把节点号翻译回房间下标
   │    └─ 统计换层次数（相邻节点楼层不同的次数）
   └─ 界面打印节点序列与累计距离，再从换层处给出「乘电梯 / 走楼梯」的指引
```

### 3.3.5 候诊队列

```
签到（患者 + 医生）
   ├─ Queue::checkIn(h, patient, doctor)
   │    ├─ 已在该医生的队伍里？   是 → 提示已签到，并给出当前位置
   │    ├─ 队列已满？             是 → 提示稍后再来
   │    ├─ 排队号 = 该医生已发出的最大号 + 1
   │    └─ h.waiting.push(w)      环形队列入队，O(1)
   └─ 打印排队位置与诊室

叫号（医生）
   ├─ Queue::callNext(h, doctor, patient)
   │    ├─ 从头扫一遍队列，遇到该医生的第一个患者
   │    │    ├─ 他已经被叫过（calledCount > 0）→ 返回 QUEUE_FIRST_CALLED
   │    │    │     不能越过队首去叫后面的人，否则「先来先看」就不成立了
   │    │    └─ 他还没被叫过 → calledCount 加一，返回他
   │    └─ 扫完没有该医生的患者 → QUEUE_EMPTY
   └─ 打印「请 XX（排队号 N）到 XX 诊室就诊」
       被叫的人仍留在队列里 —— 他要看到「已经叫到我了」，
       真正离开队列要等医生点「就诊完成」，符合实际流程。

过号（医生 + 患者）
   ├─ calledCount < kMaxPass(=2) → 记一次过号，人留在原位挡在队首
   └─ calledCount ≥ kMaxPass     → removeAt 出队，再以新的排队号重新入队（排到队尾）
        这样不守时的人不会一直堵着队伍，后来的人也不用插队

就诊完成（医生 + 患者）
   └─ Queue::finish(h, patient, doctor) → h.waiting.removeAt(i)

查看队列
   └─ 按就诊次序列出排队号、患者编号、姓名、状态（等待中 / 已叫号 / 已过号 N 次）
       并用 positionOf 算出「前面还有几个人」
```

**队列为什么只存四个字段**：姓名、诊室、科室都可以通过 `patient` 和 `doctor`
两个下标从患者表和医生表里查到，不重复保存就不会出现两处数据不一致。
队列元素因此可以很小，一条 64 位置的队列只占 1 KB。

## 3.4 出错处理约定

| 场景 | 处理方式 |
| --- | --- |
| 数据文件打不开 | `loadAll` 返回 false，提示「请先运行 build\gen_data.exe data」，程序退出 |
| 某行字段不够 | 跳过该行，打印告警并计数，继续装载 |
| 外键找不到（如医生写的科室编号不存在） | 跳过该行，打印告警并计数 |
| 同一医生同一时段重复排班 | 拒绝该行，打印告警（否则会把已有排班覆盖掉） |
| 编号重复 | 后一条覆盖前一条的索引，编号索引以最后一条为准 |
| 容量不足 | `SeqList::push` 返回 -1，跳过并计数，不做隐式扩容 |
| 按编号查不到 | `findXxx` 返回 -1，调用方必须判断 |
| 两点不连通 | `Route::between` 返回 `found = false`，界面提示不连通 |
| 号源状态变化 | 提示「号源状态刚刚发生变化，请重新选择」，不静默失败 |
| 重复签到 | `checkIn` 返回 `QUEUE_DUP`，提示已在队列中并给出当前位置 |
| 队列已满 | `checkIn` 返回 `QUEUE_FULL`，提示稍后再来 |
| 队列为空还叫号 | `callNext` 返回 `QUEUE_EMPTY`，提示没有需要叫号的患者 |
| 队首已叫号还没处理完 | `callNext` 返回 `QUEUE_FIRST_CALLED`，提示不能越过队首叫后面的人 |
| 输入的数字超出范围 | 一律拒绝并提示范围，不用 `atoi` / `sscanf`（它们对超长数字会溢出成任意值，后面的范围检查就失效了） |
| 数据超出容量上限 | 装载时明确报出是哪个表、超了多少，并提示调大哪个常量；绝不静默丢弃记录 |
| 对不在队列里的人操作 | `finish` 返回 `QUEUE_NOT_FOUND`，提示该患者不在此医生的队列中 |
| 菜单输入非数字 | 带范围的整数解析一律拒绝并重新提示，不崩溃 |

## 3.7 数据结构调试程序 `selfcheck.cpp`

一个**独立的可执行文件**（`build\selfcheck.exe`），不属于交付程序。
它的作用是把每个数据结构单独拿出来验证，确认「设计完了、也确实能用」。

**它只依赖 `ds.h` 与 `ds_sort.h`**，不 include `model.h` / `load.h` / `service.h`，
因此：

* 没有数据文件、没有科室医生这些业务概念；
* 每个结构都用**自然构造的小例子**验证 —— 数、字符、简单的结构体；
* 编译它不需要 `data\` 目录，单独就能跑。

**组织结构**：每个结构一个函数，一个断言宏负责计数与报错。

```cpp
namespace check {
  int gPassed, gFailed;
  void begin(const char* name);   // 开一个结构的检查
  void report(bool ok, ...);      // 记一条结论，失败时打印期望值与实际值
  void end();                     // 收尾，打印「全部通过」
}

void testSeqList();         // 顺序表
void testRingQueue();       // 环形队列
void testHashMap();         // 散列表
void testScheduleTable();   // 二维数组
void testWeightedGraph();   // 带权图（Floyd）
void testBipartiteGraph();  // 带权二部图
void testInsertSorted();    // 插入排序

// 主程序按名字选择要跑哪个（名字大小写不敏感）
const Entry kTests[] = {
    {"SeqList", testSeqList, "顺序表 —— 静态数组 + 长度"},
    ...
};
```

**运行方式**：

```
selfcheck                          跑全部 7 个结构
selfcheck SeqList                  只跑顺序表
selfcheck HashMap BipartiteGraph   跑指定的几个
selfcheck list                     看清单
```

退出码 0 表示全部通过，1 表示有失败项，便于接到自动化脚本里。

**断言宏必须保证表达式只求值一次**：

```cpp
#define EXPECT_INT(what, expect, actual)        \
  do {                                          \
    const long long e_ = (long long)(expect);   \
    const long long a_ = (long long)(actual);   \
    ...比较 e_ 与 a_，失败时打印两者...           \
  } while (0)
```

一开始写成「比较时求值一次、打印时再求值一次」，于是 `a.push(x)` 这种带副作用的
表达式被执行了两遍，看上去像是顺序表在出错 —— 实际上是断言宏自己的毛病。

**断言不要写得太“聪明”**：`EXPECT_INT("往返距离相同", a == b ? 1 : 0, 1)` 这种写法，
即使 a 与 b 不相等，断言也会报告通过，因为「实际值」被硬编码成了 1。
断言应当把两个待比较的量直接给出来。

**各结构的规模**：

| 测什么 | 断言数 |
| --- | --- |
| 顺序表 `SeqList` | 44 |
| 环形队列 `RingQueue` | 46 |
| 散列表 `HashMap` | 30 |
| 二维数组 `ScheduleTable` | 34 |
| 带权图 `WeightedGraph` | 62 |
| 带权二部图 `BipartiteGraph` | 69 |
| 插入排序 `insertSorted` | 47 |
| **合计** | **332** |

**为什么插入排序要单独抽成 `ds_sort.h`**：它原来是 `Triage` 类里的私有函数，
和「科室」「得分」绑在一起，想单独验证这个算法就得把整个业务层都拖进来。
抽出来之后它只认「一个数组 + 一个排序规则」，任何元素类型都能用，
也就能脱离业务单独自检 —— 这个重构正是被自检的需要逼出来的。
