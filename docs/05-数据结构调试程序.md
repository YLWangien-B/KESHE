# 数据结构调试程序说明

`src/selfcheck.cpp` —— 一个**只测数据结构**的可执行程序。

---

## 1. 它是干什么的

把 `ds.h` / `ds_sort.h` 里自己实现的每个数据结构**单独拿出来**，用一组**可预期的输入**
去调用它，把实际结果和预期结果比一比。全部通过就说明这个数据结构是对的。

**它和实际使用（医院业务）完全无关。**

| | |
| --- | --- |
| 只 include | `ds.h`、`ds_sort.h` |
| **不** include | `model.h`、`load.h`、`service.h`、`service_queue.h` |
| 需要数据文件吗 | **不需要**，编译和运行都不依赖 `data\` 目录 |
| 测试数据是什么 | 自然构造的小例子：整数、字符串、简单的结构体 |
| 断言总数 | **332 项**，全部通过 |

这一条很关键：它能脱离医院业务独立存在，也就意味着**每个数据结构都能在业务代码
写出来之前就先验证好**。写完一个结构测一个，不必等到界面接上去才发现问题。

---

## 2. 怎么运行

程序编译后是 `build\selfcheck.exe`，用命令行参数选择要测哪个结构。

```bat
rem 跑全部（7 个结构）
tools\selfcheck.bat

rem 只跑顺序表
tools\selfcheck.bat SeqList

rem 跑指定的几个
tools\selfcheck.bat HashMap BipartiteGraph

rem 看看有哪些结构可以测
tools\selfcheck.bat list
```

**名字大小写不敏感**（`seqlist`、`SeqList`、`SEQLIST` 都一样）。

**退出码**：`0` 表示全部通过，`1` 表示有失败项 —— 便于将来接到自动化脚本里。

**输出风格**：通过的不打印，**只打印失败的条目**，连同「期望什么、实际得到什么、
源码哪一行」一起给出：

```
  [失败] 队列满了
         期望：true
         实际：false
         位置：F:\dsh-workingstation\课设\src\selfcheck.cpp : 252
```

所以正常情况下输出是干净的：

```
============================================================
  数据结构调试程序
============================================================
  只测数据结构本身，与实际使用（医院业务）无关：
  没有数据文件、没有业务逻辑，每个结构都用自然构造的小例子验证。

  本次检查： SeqList RingQueue HashMap ScheduleTable WeightedGraph BipartiteGraph insertSorted
  说明：只打印失败的条目。

============================================================
  SeqList  顺序表  —— 静态数组 + 长度
============================================================
  · 访问方式是「整体遍历 + 按下标随机访问」，所以用连续内存最合适。
  -> 全部通过
...
============================================================
  检查结果
============================================================
  通过 332 项，失败 0 项，共 332 项

  全部通过。
```

### 3.1 `SeqList` 顺序表

**存储**：静态数组 + 实际长度。整个结构就是「一段连续的内存 + 用到哪儿了」。

| 验证内容 | 举例 |
| --- | --- |
| 空表状态 | 长度为 0、`empty()` 为真、`full()` 为假、容量等于模板参数 |
| 尾部追加 | `push(10)` 返回新元素下标 0，长度变 1 |
| 容量上限 | 装满后 `full()` 为真，再 `push` 返回 -1 且不改变长度、不破坏原有内容 |
| 按下标随机访问 | `a[0]` 读回 10；`operator[]` 返回引用，能就地修改 |
| 按下标删除 | `removeAt(1)` 后长度减一，**后面的元素整体前移**（`a[1]` 变成原来的 `a[2]`） |
| 删除端点 | 删头、删尾都正确 |
| 越界与负数 | `removeAt(3)`、`removeAt(-1)` 返回失败且不改变长度 |
| 清空 | `clear()` 后长度为 0，且能重新 `push` |
| 退化容量 | 容量为 1 的表：放得下一个，第二个返回 -1 |
| 存结构体 | `struct Row{int id; char name[8];}` 能整体拷贝、能就地修改 |

### 3.2 `RingQueue` 环形队列

**存储**：静态数组 + 头下标 + 尾下标 + 长度。头尾走到数组末尾时绕回开头，
**出队腾出来的位置能被后来的入队循环使用**。

| 验证内容 | 举例 |
| --- | --- |
| 先进先出 | 依次入队 1 3 5，出队顺序就是 1 3 5 |
| **回绕** | 先出队两格让 `head` 前移，再入队三次让 `tail` 绕回数组开头，此后按排队次序读出的仍是 5 7 9 11（物理位置是错开的） |
| 回绕后次序不乱 | 绕了一圈之后全部出队，次序仍是先进先出 |
| 队满队空 | 满队列 `push` 返回 false；空队列 `pop` 返回 false |
| 按次序访问 | `at(0)` 是队首而非数组第 0 格 |
| 按次序删除 | `removeAt(1)` 删中间那个，其余元素的相对次序不变 |
| 可写访问 | `at(i)` 的写版本能就地修改队内元素，用于把「已叫号次数」加一 |
| 清空 | `clear()` 后为空，且能重新入队 |
| **反复回绕** | 容量 8 的队列反复进出 30 轮（多次回绕），次序始终正确 |

> 回绕是这个结构的核心：不做回绕（普通数组队列）的话，出队后前面的位置就永远用不上了。

### 3.3 `HashMap` 散列表

**存储**：桶数组（211 个桶）+ 结点池（1024 个结点）。每个桶挂一条同义词链，
**落进同一个桶的键挂在同一条链上**，靠 `strcmp` 分辨。

| 验证内容 | 举例 |
| --- | --- |
| 插入与查找 | `put("A", 0)` 后 `get("A", out)` 命中且 `out == 0` |
| 查不到 | 没插过的键、空键、大小写不同的键（`"A"` 与 `"a"` 是不同键）都返回 false |
| **同名键覆盖** | 重复 `put("A", 88)` 不新增结点（`size()` 仍是 3），且能查回新值 88 |
| **大量键必然冲突** | 连续插入 200 个键（`K000`…`K199`），结点数正好 200，且**全部能查回原值** |
| 前缀相近的键 | 26 个单字母键全部正确 |
| 清空 | `clear()` 后结点数为 0、原键查不到、还能重新插入 |

### 3.4 `ScheduleTable` 二维数组

**存储**：二维静态数组 `slot_[行][列]`，**两个下标就是主键**，定位是一次下标运算。

| 验证内容 | 举例 |
| --- | --- |
| 行列越界 | `validDay(7)`、`validDay(-1)`、`validSlot(4)`、`validSlot(-1)` 都是假 |
| 未使用与已使用的区分 | 刚建好时所有格子 `assigned()` 为假；写过的格子为真 —— 这样才能区分「没填过」和「填了但值是 0」 |
| 两个下标互不干扰 | 写 `(2,1)` 不影响同一行的 `(2,2)`、同一列的 `(1,1)` |
| 数量增减 | 扣掉 1 个后余量变 14，退回后变回 15，且格子仍是「已使用」 |
| 标记位 | 置了停用标记的格子仍是「已使用」，但余量按 0 返回 |
| **余量不为负** | 故意造成超额预约时按 0 返回，不出现负数（否则「还有没有余量」的判断会反过来） |
| 清空 | `clear()` 后全部回到未使用 |

### 3.5 `WeightedGraph` 带权图

**存储**：邻接矩阵 `dist_[i][j]`（不可达用一个很大的数 `kInf` 表示）+ 路径矩阵 `next_[i][j]`。
**算法**：Floyd，三重循环逐轮放宽「允许经过哪些中转点」，一轮放一个。

| 验证内容 | 举例 |
| --- | --- |
| 不可达的表示 | 没加边时 `distance` 返回 `kInf`，`reachable` 为假 |
| 无向 | 0 到 1 是 10，1 到 0 也是 10 |
| **加边取较小权值** | 同一对顶点重复加边时保留最短的那条（10 → 4 覆盖，30 不覆盖 10） |
| 跑 Floyd 之前 | 没有直接边的两点仍不可达 |
| **Floyd 中转** | 边是 `0-1=4、1-2=10、2-3=5、0-4=100`，跑完后 `0→2 = 14`、`0→3 = 19`、`1→3 = 15`，而直达的 `0→4` 仍是 100（绕路要 119，更贵） |
| 矩阵对称 | `0→3` 与 `3→0` 相等 |
| **路径还原** | `0→3` 途经 `0 1 2 3` 四个顶点；绕路的 `3→4` 途经 `3 2 1 0 4` 五个顶点 |
| **孤立顶点** | 另建一个谁也不连的顶点，与谁都不连通，`buildPath` 返回 0 |
| **绕路胜过直达** | 直达 100、绕路 2 时取 2，且还原出的路径确实走绕路 |
| 越界与非法参数 | 顶点越界、负数顶点、负权值一律拒绝；越界查询返回 `kInf` |
| 容量不足 | 路径缓冲区放不下整条路径时返回 0 |
| 重新 init | 顶点数保留，边全部清掉 |

### 3.6 `BipartiteGraph` 带权二部图

**存储**：两侧顶点表 + **前向星邻接表**（链头数组 + 边集）。
**每条边在边集中占两个结点，两侧各挂一次。**

| 验证内容 | 举例 |
| --- | --- |
| 两侧顶点各自独立 | 左侧 4 个、右侧 3 个，各自编号从 0 开始 |
| 顶点去重 | 重复加同名顶点返回原有顶点号，不新增 |
| 按名字查找 | `findSymptom("beta")` 得到 1，查不到返回 -1 |
| 加边要求两端存在 | 右侧顶点数还没设时加边被拒绝 |
| 权值范围 | 权值 0、负数、超过上限都被拒绝 |
| **重复加边取大** | 同一对顶点重复加边不新增边，只在权值更大时更新 |
| **遍历方向一** | 左侧顶点 → 它关联的右侧顶点：`delta` 关联 2 个 |
| **遍历方向二** | 右侧顶点 → 它关联的左侧顶点：顶点 0 关联 3 个 |
| **两侧边数必须一致** | 从左侧数出的边数 = 从右侧数出的边数 = 6，边集结点数 = 6 × 2 = 12 |
| 越界的遍历起点 | 返回 -1，不会崩 |
| 清空 | 两侧顶点数与边数都归零，还能重新加顶点 |

> **「两侧边数一致」是这个结构最关键的对称性**。每条边在两侧各挂一次，
> 如果一条边的两个端点结点共用一个 `next` 字段，两条链会互相覆盖，
> 表现就是「从一侧查得到、从另一侧查不到」。这一组断言专门盯着这个。

### 3.7 `insertSorted` 插入排序

**算法**：把新元素插到「已经排好序」的数组里的正确位置，后面的元素整体后移。
**数组满了之后，只有能排在最后一名前面的才挤掉它**（即只保留前 cap 名）。

| 验证内容 | 举例 |
| --- | --- |
| 空数组插一条 | 长度为 1，内容正确 |
| 降序保持 | 依次插 1 9 6 8 3，结果是 `9 8 6 3 1` |
| **更好的成绩挤入** | 榜满（`9 8 6 3 1`）时插分数 2：进榜，垫底的分数 1 被挤出去 |
| **更差的成绩丢弃** | 再插分数 0：被丢弃，数组不变 |
| 最高分进第 1 位 | 插分数 100：进第 1 位，其余依次后移 |
| **同分稳定** | 5 条同分的插满后，第 1 位仍是先来的；再来一条同分的挤不进去 |
| 容量为 1 | 更差的挤不进、更好的能替换、再插更差的又挤不进 |
| **换比较规则** | 用 `Ascending<int>` 插 `0 7 4 1 8 5`，得到升序 —— 说明算法与元素类型、排序方向都无关 |

## 4. 程序是怎么组织的

### 4.1 文件结构

```
src/selfcheck.cpp
├── 命名空间 check        自检框架：计数与报错
│     begin(name)          开一个结构的检查
│     report(...)          记一条结论，失败时打印期望值/实际值/源码位置
│     end()                收尾，打印「全部通过」
│     note(text)           一句说明，交代这个结构在验什么
│
├── 断言宏                EXPECT_INT / EXPECT_TRUE / EXPECT_FALSE / EXPECT_STR
│
├── 七个测试函数（各自独立）
│     testSeqList()          第 124 行
│     testRingQueue()        第 226 行
│     testHashMap()          第 335 行
│     testScheduleTable()    第 435 行
│     testWeightedGraph()    第 526 行
│     testBipartiteGraph()   第 657 行
│     testInsertSorted()     第 822 行
│
└── 主程序                按命令行参数选择要跑哪个
      kTests[]               结构名 → 测试函数 的对照表
      main()                 解析参数、逐个跑、汇总结果
```

一共 935 行，其中测试内容约 700 行。

### 4.2 断言宏

四条宏，覆盖常见的比较：

| 宏 | 用途 |
| --- | --- |
| `EXPECT_INT(说明, 期望, 实际)` | 两个整数相等 |
| `EXPECT_TRUE(说明, 条件)` | 条件为真 |
| `EXPECT_FALSE(说明, 条件)` | 条件为假 |
| `EXPECT_STR(说明, 期望, 实际)` | 两个字符串相等 |

**它们都必须保证待检表达式只求值一次**：

```cpp
#define EXPECT_INT(what, expect, actual)        \
  do {                                          \
    const long long e_ = (long long)(expect);   \
    const long long a_ = (long long)(actual);   \
    ...比较 e_ 与 a_，失败时打印两者...           \
  } while (0)
```

### 4.3 主程序的结构表

```cpp
struct Entry {
  const char* name;      // 命令行里用的名字
  void (*run)();         // 对应的测试函数
  const char* brief;     // list 时显示的一句话说明
};

const Entry kTests[] = {
    {"SeqList", testSeqList, "顺序表 —— 静态数组 + 长度"},
    {"RingQueue", testRingQueue, "环形队列 —— 先进先出，出队位置循环复用"},
    {"HashMap", testHashMap, "散列表 —— 链地址法，字符串键 -> 下标"},
    {"ScheduleTable", testScheduleTable, "二维数组 —— 两个下标直接定位"},
    {"WeightedGraph", testWeightedGraph, "带权图 —— 邻接矩阵 + Floyd 最短路"},
    {"BipartiteGraph", testBipartiteGraph, "带权二部图 —— 两侧顶点 + 前向星邻接表"},
    {"insertSorted", testInsertSorted, "插入排序 —— 有序插入，满了按规则挤入"},
};
```

**加一个新的数据结构时，只要三步**：

1. 写一个 `void testXxx()` 函数，用 `check::begin` / 断言 / `check::end` 组织；
2. 在 `kTests[]` 里加一行；
3. 重新编译。参数解析、计数、汇总、报错都不用手动改。

## 6. 写这个程序时踩到的坑

### 6.1 断言宏把表达式求值了两次

一开始写成「比较时求值一次、打印时再求值一次」：

```cpp
// 错误写法
check::report((long long)(expect) == (long long)(actual), what,
              /* 打印期望值 */, /* 打印实际值 */);   // actual 又被算了一遍
```

于是 `a.push(10)` 这种**带副作用**的调用被执行了两遍 —— 顺序表被 push 了双倍数据，
长度、下标、删除结果全都对不上，看上去像是**被检的顺序表在出错**。

**教训**：断言宏必须保证待检表达式只求值一次，一律先存进局部常量。

### 6.2 断言写得太“聪明”

有一处写成：

```cpp
// 错误写法：即使 forth 与 back 不相等，断言也会报告通过
EXPECT_INT("往返距离相同", forth.totalDistance == back.totalDistance ? 1 : 0, 1);
```

「实际值」被硬编码成了 1，比较结果永远等于 1。断言应当把**两个待比较的量直接给出来**：

```cpp
EXPECT_INT("往返距离相同", forth.totalDistance, back.totalDistance);
```

### 6.3 期望值算错，不怪代码

有几条断言是我想当然写的：

| 写错的期望 | 实际情况 |
| --- | --- |
| 把 `push` 的返回值当成「长度」 | `push` 返回的是**新元素的下标**；`pop` 返回的是**成功与否** |
| 一个 5 个顶点的小图以为是两半不连通 | 其实**整体连通**（3 经 2、1、0 到 4，距离 119）。要验证「不可达」得另建一个谁也不连的孤立顶点 |
| 「满了之后更差的应当挤入」 | 反了 —— 应当是**更好的成绩挤掉垫底的那条**（只保留前 cap 名） |

### 6.4 一个真 bug：插入排序的挤入方向写反

把插入排序从 `Triage` 类里抽成通用函数时，「满了之后要不要挤入」写反了：

```cpp
// 错误：比最后一名差才挤入 —— 榜单满了以后，更好的成绩反而进不来
if (!less(a[cap - 1], v)) return;
```

**实际影响**：导诊推荐 Top-5 榜满之后，**得分更高的科室挤不进来，会被直接丢掉**。

而这个 bug 一开始**没被自检抓到**，因为**那条断言本身也写反了**。最后是写了个独立
的探针程序，把每一步的实际行为打印出来，才把两边的方向同时看清：

```
  现在 less(low, a[4]) = less((分2),(分1)) = 1
  插 (id99,分2)        n=5 : 9/id2 8/id4 6/id3 3/id5 2/id99
  应当是 9/id2 8/id4 6/id3 3/id5 1/id7 不变      ← 我的断言写的
```

### 6.5 三条教训

1. **自检程序自己也会错。** 自检失败时，第一步要判断是「被检代码错了」还是
   「期望值写错了」。
2. **判断的办法是看实际行为，不是对着断言猜。** 用一个独立的小程序把每一步打印
   出来，比反复读断言代码有效得多。
3. **断言要写得笨一点。** 期望值直接给具体数字，比较的量直接给出来，
   不要在断言里做运算 —— 自检程序本身不应该有任何需要推敲的逻辑。
