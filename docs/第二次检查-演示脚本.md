## 四、场景 2：智能导诊（2 分钟）

> **数据结构：带权二部图**

```
患者端 → 底部「导诊」→ 勾选：发热、咳嗽、胸闷 → 点「开始导诊」
```

### 指着结果表讲

| 列 | 讲解 |
|---|---|
| 名次 / 科室 | 按匹配得分从高到低 |
| 得分 | 所选症状与该科室的**关联强度之和** |
| 命中症状 | 具体哪几个症状匹配上了 |
| 该科室医生 | 该科室医生，按**患者评分 + 职称**排序 |

**讲解词**：
> "导诊用的是**带权二部图**：左边 25 个症状、右边 12 个科室，边权 1~5 是关联强度。
>
> 选完症状后，对每个科室做**邻域加权求和**，再用**插入排序**取前几名。同样的输入永远得到同样的推荐 —— 因为插入排序是稳定的，得分相同的科室保持先来后到。"
>
> "题目要求『基于词频统计的匹配策略』。我最初做过按患者描述分词匹配，后来改成按症状勾选 —— 因为分词需要词库，而题目不允许用类库。按序号勾选更稳定、结果可复现。"

## 五、场景 3：查医生 + 在线预约 + 冲突检测（3 分钟）

> **数据结构：顺序表 + 散列表 + 二维数组**

### 第 1 步：查医生

```
患者端 → 「预约」→ 二级标签「医生查询」→ 按科室 → 呼吸内科 → 查询
```

**讲解词**：
> "医生存在**顺序表**里，同时维护了**散列表**做『编号→下标』索引。
> 按编号查是 O(1)（散列）；按科室/职称/擅长这类条件查是一次线性筛选 —— 规模只有 36 条，线性筛选比维护三个索引更划算。"

### 第 2 步：预约

```
患者端 → 二级标签「在线预约」
      → 医生选一位 → 点号源格子「周一上午」
      → 点「生成预约凭证」
```

**弹出**：

```
预约凭证 TK0001
患者     P1 张伟
科室     心血管内科
医生     D1 王秀英（主任医师）
时间     周一上午
地点     门诊楼1层心血管内科诊室
该时段剩余号源   14
```

### 指着号源格子讲

```
        周一      周二      周三  ...   周日
上午   15 / 15   不出诊    15 / 15
下午   不出诊    10 / 10   不出诊
```

| 特征 | 含义 |
|---|---|
| 格内数字 | `余号 / 总号源` |
| 绿 / 黄 / 红 | 充足 / 紧张（余≤3）/ 已满 |
| 灰 | 该时段不出诊或已停诊 |

**讲解词**：
> "排班用**二维数组**：每位医生一张 `7 天 × 2 时段` 的表，两个下标就是主键，查询 **O(1)**。
>
> 预约时四件事连着做完、中间不让出执行权：**检查停诊 → 检查余量 → 扣减余号 → 递增版本号**。这就是题目实现提示第 4 条说的『不会超卖』。"

### 第 3 步：冲突检测（自选功能）

```
换个医生，还是同一个时段（周一上午）→ 生成预约凭证
```

**结果**：
```
你在该时段已有预约 TK0001，不能重复预约。请先到「预约管理」取消原预约。
```

**讲解词**：
> "这是我自己加的一项。之前同一个人可以在同一时段约两个不同科室 —— 到那天两份凭证都有效、两边都能签到，人却只有一个。现在会拦住，并告诉你是哪张凭证。"

## 七、场景 5：就诊路线（2 分钟）

> **数据结构：带权图 + Floyd 最短路**

```
患者端 → 「我的」→ 二级标签「就诊路线」
      → 起点：门诊楼1层 · RA100 电梯口
      → 终点：选一个远一点的房间
      → 点「查询路线」
```

**指着左侧明细表**：
> "用**带权图**：每个房间是顶点，能走过去就画一条边，边权是距离。
>
> **装载时用 Floyd 一次算出任意两点最短路**，所以查询只是查表 + 还原路径。这是用一次 O(n³) 预处理换每次 O(1) 查询 —— 顶点只有 48 个，预处理量约 11 万次，可以忽略。
>
> 左边明细和右边平面图是同一份数据，查询出的路线会直接描在图上，换楼层单独给指引。"

### 一键导入目的地（自选功能）

```
点「导入目的地」→ 选一条预约 → 终点自动变成该医生的诊室，路线立刻画出来
```

**讲解词**：
> "之前要查路线，得在 48 个房间的下拉框里翻出『我该去哪个诊室』。现在从预约里选一条，终点自动填好并算出路来。"

## 九、场景 7：就诊完成 → 患者评价 → 评分参与推荐（3 分钟）

> **拓展要求第 3 条**（这是四条里最有内容的一条）

### 第 1 步：就诊完成

```
管理端 → 点「就诊完成」
```

**讲解词**：
> "就诊完成会把对应预约标记为『已完成』—— 这是患者能评价医生的前提。"

### 第 2 步：患者评价

```
患者端 → 「我的」→「预约管理」
      → 状态变成「已完成」，评价列显示「待评价」
      → 选中这条 → 点「评价选中的就诊」→ 打 5 分
```

**讲解词**：
> "这里有个细节：**只有状态是『已完成』的预约才能评价**。
>
> 为什么？如果谁都能评，患者可以随便刷分。必须医生在管理端点过『就诊完成』，系统才认定这次诊疗真的发生过。而且同一条预约只能评一次。"

### 第 3 步：评分影响推荐（关键讲解）

```
管理端 → 「资源导航」→「医生查询」→ 该医生评分变了
患者端 → 「导诊」→ 重新导诊 → 看着科室医生那一列
```

**讲解词（本场最重要的一段）**：
> "题目原文是『患者就诊后可对医生进行评价，**在科室预约推荐时参考评分**』。
>
> 这里有个设计取舍值得说：**我没有把评分直接加进科室得分**。
>
> 科室得分衡量的是『症状匹配度』（二部图边权和），评分衡量的是『医生好不好』，两者数值范围都是 1~5，但含义完全不同。直接相加会出现『医生态度好』盖过『症状根本不匹配』，推荐出无关科室。
>
> 所以做了**分层**：
> - **科室排序**：只看症状匹配（不变）
> - **医生排序**：评分 50% + 职称 30% + 该时段余号 20%
>
> 这其实也是真实挂号的逻辑：先定科室，再在科室内挑医生。
>
> 补一个细节：**无人评价的医生评分项按 60 分中性处理** —— 既不惩罚新医生，也不让他占便宜。"

### 技术点（被追问时）

```cpp
// DoctorRank::score()
rating(0~100) × 50% + 职称分(0~100) × 30% + 余号比例(0~100) × 20%
// 职称分：主任医师 100 / 副主任 75 / 主治 50 / 住院 25
// 无人评价 → rating 按 60 算
```

## 十、场景 8：排班管理 —— 停诊自动改约 + 换班（4 分钟）

> **拓展要求第 2 条**（这是四条里最容易被问的一条，也是最容易讲出深度的一段）

### 第 1 步：制造场景

```
患者端先约 3 条（不同患者、同一位医生的同一时段）
:: 可用管理端「患者服务 → 预约管理」帮忙约，或直接切换患者端登录不同人
```

### 第 2 步：停诊 + 自动改约

```
管理端 → 左侧「排班管理」→ 视角「按医生」→ 选那位医生
      → 点一下那个号源格子选中它
      → 点「设为停诊」
```

**结果提示**：
```
已停诊：D1 王秀英 周一上午。3 位患者已自动改约到其它时段（新凭证见其预约管理）
```

**讲解词**：
> "注意这里不只是『通知已停诊』。如果只通知，患者还得自己从头重约一遍 —— 这不是通知，是『通知你自己想办法』。
>
> 所以停诊时会同时帮他找替代时段，按优先级：
> **同医生同一天另一个时段 → 同医生其它天同时段 → 同科室其它医生同时段**。
> 找到就生成新凭证，原记录标记为『因停诊改约』留痕。找不到才退化成『因停诊取消』，并明确告诉管理者有几位没着落。"

### 第 3 步：换班（重点）

```
管理端 → 还是「排班管理」，选中另一个有预约的时段
      → 点「换班…」
```

弹出：
```
当前：D1 王秀英 · 周一上午
换成：[D3 张淑华（主治医师 · 余号 15）▼]
该时段现有 1 条预约，会一起转给新医生。
```

确定后：
```
换班完成：周一上午 由 王秀英 改为 张淑华，1 条预约已随之转移
```

**讲解词**：
> "**停诊和换班的语义完全不同**：
>
> | | 停诊 | 换班 |
> |---|---|---|
> | 号源 | 作废 | **保留**（还是那些号） |
> | 患者 | 要改约到别的时间 | **什么都不用改** |
> | 本质 | 这个时段不看病了 | 还看病，换个人看 |
>
> 现实场景：王医生周一上午临时有个会，让同科室张医生替她出这个门诊 —— 患者照常来、照常看，只是换了个大夫。这种情况**不能停诊**（停了患者要改时间），只能换班。
>
> 实现上最关键的是**余量校验**：目标医生那个时段装不装得下这些患者。装不下就拒绝，否则会超卖。"

### 技术点

```cpp
// Shift::transfer() 四步
① 校验原时段有排班、目标时段出诊且未停诊
② 先数清要转移多少条预约
③ if (目标余量 < 待转移条数) 拒绝        ← 防超卖
④ 预约记录的 doctor 字段改掉 + 号源在原时段清零、新时段加上
```

### 第 4 步：患者端验证

```
切患者端 → 「我的」→「预约管理」
      → 看状态：「因停诊改约」/「因停诊取消」
      → 换班的记录：医生名字变了，时间地点不变
```

## 十四、常见提问与回答

### Q1：为什么拆成两个程序？

> "患者和医院的使用场景完全不同：患者只关心自己的预约，管理端要管全院。放在一个界面里，要么患者能看到别人的数据，要么管理端被无关按钮淹没。
> 拆开还逼出了并发问题 —— 两个进程改同一份数据，正好能讲清楚怎么保证不冲突。"

### Q2：不用网络，两个程序怎么共享数据？

> "**内存映射文件 + 命名互斥体**。
> 两个进程映射同一个 `data/state.bin`，操作系统让它们共享同一批物理页，一方写入另一方立刻能看到，不需要传数据、不需要序列化。
> 互斥体是 Windows 的命名内核对象，名字相同就是同一把锁。"

### Q3：两个人同时抢最后一个号会怎样？

> "『检查余量』和『扣减余量』在同一个临界区里，中间不让出 CPU，所以不可能两个人都通过检查。
> 压力测试验证过：不加锁 4000 次并发操作丢 34%，加锁后 4000 次全部正确。"

### Q4：数据 371KB，每次同步会不会很慢？

> "**没有『同步』这个动作**。不是 A 发给 B，而是两个进程看着同一块内存，延迟是内存级的。
> 界面那边只轮询一个全局写计数，每 700 毫秒检查一次，变了才重读重绘。"

### Q5：六种数据结构为什么这么选？

> "按操作特点选：
> - **顺序表**：数据量固定、要按下标随机访问
> - **环形队列**：候诊只在一头进一头出，出队位置能复用
> - **散列表**：编号查下标要 O(1)
> - **二维数组**：排班主键就是两个下标（日期、时段）
> - **带权图**：房间之间能走过去，边权是距离，求最短路
> - **带权二部图**：症状和科室两类顶点，只有跨类连边，边权是关联强度"

### Q6：评分为什么不会把好科室挤掉？

> "因为**分层**：科室排序只看症状匹配度，评分只参与**科室内医生**的排序。评分再高也不会让一个无关科室排到第一。"

### Q7：停诊和换班再讲一遍区别？

> "停诊 = 这个时段**没号了**，患者要改时间；
> 换班 = 号**还在**，只是换个医生看，患者什么都不用改。
> 医生临时有事，多半是找同事替，这是换班；找不到人替，才是停诊。"

### Q8：这些改动有没有破坏原来的功能？

> "字符界面一直在跑回归测试，`tools\check.bat` 逐字节比对，一直是通过的。
> 而且业务层是共用的 —— 字符界面、患者端、管理端调的是同一批函数。"

### Q9：图形界面为什么选 Qt？

> "题目要求图形化展示。Qt 自带表格、树、停靠窗口、图形视图这些控件，楼层平面图用 QGraphicsView 画。
> 界面层和业务层完全分开 —— 业务层不知道界面用的是 Qt。"
